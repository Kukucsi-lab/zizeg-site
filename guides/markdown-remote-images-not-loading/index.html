Find the cause before changing the setting

An online image.
A missing picture.

Check whether the picture needs approval, a working URL, or a local replacement.

The quick answer

First check whether the image URL starts with https:// or http://. If Zizeg shows a blocked-image placeholder, approve the image when you want to load it. If it still fails, check the URL, connection, and server access. Remote-content settings cannot repair an unavailable image.

Start with the image destination.

Open the document in Zizeg—double-click in Finder if it is your default Markdown app. Preview (⌘1) shows the formatted document; Split (⌘3) shows Source alongside it. Your default viewing mode may already show both.

This is an illustrative URL. The image is fetched from a server, rather than read from a folder beside the Markdown file.

Look at the destination in Source. An https:// or http:// image is remote. A path such as Notes-assets/chart.png is local; use the local-image repair guide for that case. A data:image/… destination contains embedded data and is a separate image-storage choice.

A click-to-load placeholder is an intentional control. It does not by itself mean the Markdown is wrong or the server is unavailable. After approval, Zizeg still needs a reachable response that validates as an image.

Load the image you need, or choose a broader policy.

Under Preferences → Safety → Remote content, Zizeg offers three choices:

  • Block and click to load (default): images start blocked; approve one from its placeholder.
  • Always allow: request remote images without per-image approval.
  • Ask every time: ask before loading remote content for the document.

For an occasional missing picture, approving that image is usually enough. Loading it contacts the image server and can reveal that the document was opened, so check the domain before approving an unfamiliar source.

Per-image approvals last for the current editing session. Approving one occurrence also approves other occurrences of the same exact URL for that session. Seeing a blocked placeholder again after reopening can therefore be expected behavior.

For an unfamiliar document, see reading Markdown with control over remote content.

Check the URL and the server response.

  1. Check the complete image destination in Source.Look for a mistyped address, a copied page link, or a URL that has changed.
  2. Check access to the resource.A server may be offline, the link may have expired, or the resource may require a login. An image visible in your signed-in browser does not prove another app can fetch it.
  3. Try a local image when appropriate.If you have permission to use the picture and can obtain the file, insert it locally using paste, drag-and-drop, or Format → Image…. This removes the remote server dependency for that copy.

See the image insertion guide for local pictures. Correcting a source reference or inserting a replacement requires editing access through a Lifetime Unlock or an active subscription. Reading remains free.

Preview approval is not the final sharing check.

When exporting a document with remote images, Zizeg shows a picker for the referenced pictures. Images already approved in Preview start selected. Use Select All, Select None, or choose the individual images you want included.

Accessible selected images are embedded in the HTML or PDF output. Unchecked or failed images are not left as live remote-image URLs. Open the exported file and check that the pictures your reader needs are present.

Follow the standalone HTML guide or PDF export guide for the full steps.

Ordinary web links are different: they do not fetch their target content during rendering and do not appear in the remote-image picker.
