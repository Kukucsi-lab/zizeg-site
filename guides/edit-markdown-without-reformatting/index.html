Fix the wording in a readable document, with the Markdown source right beside you whenever you need it.

The quick answer

When you edit in Preview, Zizeg usually changes only the blocks you edited and leaves the rest as written. Simply opening and reading a file doesn’t rewrite it. If Zizeg does rewrite part of the source, your content stays the same: only the Markdown syntax is standardized to GitHub Flavored Markdown (GFM), so it keeps rendering cleanly. For direct control over the syntax, edit in Source.

Edit the document where you can read it.

You have a Markdown file with a heading, a few paragraphs, and a list. You want to correct a sentence or change a deadline. Open it in Zizeg and make that change directly in the formatted Preview.

Preview is editable: click into the text and type. You can also use shortcuts, toolbar controls, or the app menus to apply formatting in either Preview or Source. The two views stay in sync.

That is the whole task. You don’t need to rebuild the document or convert it to another format. Your working file remains Markdown.

See the readable document and its Markdown together.

  1. Open your .md file.If Zizeg is your default Markdown app, just double-click the file in Finder.
  2. Choose Preview or Split.Preview (⌘1) gives you the formatted document. Split (⌘3) puts Source alongside it. If either is your default viewing mode, the formatted view is already there when the file opens.
  3. Edit in the view that suits the change.Correct the sentence in Preview, or type directly in Source. Changes in either editor update the other.

Zizeg autosaves ordinary edits in place. If you want to try changes in a separate version, choose File → Save As… (⇧⌘S) first.

Your Markdown conventions are still within reach.

Sometimes the source text itself matters: you prefer * list markers, a particular heading style, or specific indentation for a shared project. Use Source (⌘2) to make those changes directly, with Preview available to show the result.

For everyday Preview edits, Zizeg normally updates the changed lines within the affected blocks and keeps the surrounding Markdown as written. Occasionally Zizeg rewrites an edited block, or more of the file. Your content stays the same; only the Markdown syntax is standardized to GFM so it keeps rendering cleanly. When exact syntax or whitespace matters, use Source.

You can check the edited lines in Split without turning every small wording change into a source-review exercise. If your project uses version control, its usual diff review remains a useful final check.

Continue working with the same plain file.

There is no vault to set up and no proprietary document format to convert back. Keep the .md in its existing folder, make the change, and continue with your project.

If the file contains YAML front matter, Zizeg displays it separately in Preview. Use Edit in Source when you want to change that metadata.

To share a finished reading copy, export PDF or standalone HTML while keeping the Markdown for later edits. If the same source looks different in another viewer, see why Markdown appearance varies between apps.
